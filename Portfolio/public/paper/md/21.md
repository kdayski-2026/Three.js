## roboticsParser

Парсер и API‑сервис для сбора и анализа данных по пуллам ликвидности PancakeSwap на Binance Smart Chain.

### Основные компоненты
- **`poolinfo.js`**: периодически опрашивает смарт‑контракт `MasterChef`, пары ликвидности и API CoinGecko. Расчитывает показатели по каждому пулу (резервы, цены токенов, ликвидность, доходность и т.п.) и сохраняет данные в MongoDB.
- **`api.js`**: HTTP‑API на базе `express`, которое читает данные из MongoDB и:
  - при запросе последней выборки или данных за конкретную дату генерирует Excel‑файл `Excel.xlsx` и отдает его клиенту;
  - при запросе по конкретной паре токенов возвращает JSON‑данные.
- **`logger.js`**: логирование работы парсера (в т.ч. в файл `combined.log`).
- **`config/network.json`**: настройки сети и базы данных (RPC‑endpoint BSC, строка подключения MongoDB, имя базы и коллекции, порт API).
- **`config/main.json`**: ABI и адреса контрактов (`MasterChef`, токены, LP‑пары), а также URL CoinGecko для получения цен.

### Зависимости
Проект использует:
- **Node.js** и **npm**
- **express** — HTTP‑сервер и роутинг
- **mongodb** — работа с MongoDB
- **web3** — взаимодействие с BSC
- **axios** и **retry-axios** — HTTP‑запросы к внешним API с повторными попытками
- **node-libcurl** — низкоуровневые HTTP‑запросы
- **excel4node** — генерация Excel‑файлов
- **winston** — логирование
- **nodemon** — перезапуск сервера при изменениях (для разработки)

### Запуск
1. **Установите зависимости**
   ```bash
   npm install
   ```

2. **Настройте конфигурацию**
   - при необходимости отредактируйте `config/network.json` (RPC‑endpoint, строка подключения MongoDB, порт);
   - при необходимости отредактируйте `config/main.json` (адреса контрактов, ABI, адрес кошелька `myAddress`).

3. **Запустите парсер пуллов**
   ```bash
   node poolinfo.js
   ```
   Скрипт сразу выполнит один проход по всем пулам и затем будет автоматически повторяться раз в час, сохраняя новые срезы в MongoDB.

4. **Запустите API‑сервер**
   ```bash
   npm start
   ```
   По умолчанию сервер слушает порт, указанный в `config/network.json` (например, `3847`).

### Эндпоинты API
- **GET `/pairs`** — разные режимы в зависимости от параметров запроса:
  - без параметров: берется самая свежая выборка данных, по ней формируется Excel‑файл `Excel.xlsx`, который отдается на скачивание;
  - `?date=YYYY-MM-DD` — данные за указанную дату (по последней выборке за этот день), также в виде Excel‑файла;
  - `?t1=TOKEN0&t2=TOKEN1&d1=DATE_FROM&d2=DATE_TO` — данные по конкретной паре токенов в виде JSON за указанный интервал (даты должны быть в формате, корректно парсимом `new Date()`).

### Требования
- запущенный и доступный **MongoDB** (локально или в сети), строка подключения задаётся в `config/network.json`;
- доступ к RPC‑ноде **BSC** (поле `provider` в `config/network.json`);
- стабильный доступ к **CoinGecko API** (поле `tokenPriceApiUrl` в `config/main.json`).

### Логи
- Основная информация о запуске и времени работы парсера пишется в `combined.log` через `winston`.

### Лицензия
Проект распространяется под лицензией **ISC** (см. `package.json`).
