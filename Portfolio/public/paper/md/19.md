# git

Небольшой набор bash‑скриптов для **клонирования/обновления** выбранных репозиториев и **деплоя** (сборка + запуск/перезапуск через `pm2`).

## Что внутри

- **`config`** — список проектов и репозиториев (массивы).
- **`deploy.sh`** — интерактивно выбирает проект/репозиторий, затем:
  - `git clone <repo>`
  - `npm i --force`
  - `npm run build`
  - `pm2 start servestart.sh --name <app>`
- **`update-git.sh`** — интерактивно выбирает проект/репозиторий, затем:
  - `git up` (обновление репозитория; требуется алиас/скрипт `git-up`)
  - `npm i --force`
  - `npm run build`
  - `pm2 restart <app>`

## Требования

- **Linux/macOS/WSL** (скрипты — `#!/bin/bash`).
- **git**, **Node.js + npm**, **pm2** (`npm i -g pm2`).
- **`servestart.sh`** в корне клонированного проекта (используется в `deploy.sh`).
- Команда **`git up`** должна существовать в окружении (см. ниже).

## Использование

Из папки `git/`:

```bash
chmod +x deploy.sh update-git.sh
./deploy.sh
```

или обновление уже развернутого проекта:

```bash
./update-git.sh
```

Скрипт попросит выбрать:

1) проект из `projects=(...)`  
2) тип репозитория из `options1/2=(...)`  

и дальше выполнит шаги деплоя/обновления.

## Настройка `config`

Сейчас логика такая:

- `projects=(...)` — список “групп” (проектов).
- `options1=(...)`, `options2=(...)` — варианты выбора для проекта №1 и №2.
- `git1=(...)`, `git2=(...)` — ссылки на репозитории для проекта №1 и №2 (индексы должны совпадать с `optionsN`).

Чтобы добавить новый “проект”:

- добавьте имя в `projects`
- создайте `options3=(...)` и `git3=(...)` (и так далее)

## Примечания

- В `deploy.sh` репозиторий клонируется в домашнюю директорию пользователя (`~$USER`), а затем выполняются команды в папке проекта.
- В `update-git.sh` ожидается, что папка проекта уже существует в `~/<name>`.
- Если `git up` у вас не настроен, замените его на подходящую команду (например `git pull --rebase`) в `update-git.sh`.
