## Container Manager

Менеджер Docker-контейнеров, который автоматически масштабирует количество запущенных контейнеров в зависимости от загрузки CPU и памяти, а также от доступного лимита контейнеров.

### Основные возможности

- **Автоматический мониторинг нагрузки**: периодически замеряет загрузку CPU и использование памяти.
- **Ограничение по максимальной нагрузке**: новые контейнеры запускаются только при загрузке ниже заданного порога (`MAX_LOAD_PERCENT`, по умолчанию 80%).
- **Учёт максимального количества контейнеров**: вызывает скрипт `availability_detect.sh` для определения максимально допустимого числа одновременно работающих контейнеров.
- **Автоматический запуск контейнеров**: поднимает новые контейнеры с помощью `docker run` (с переменной окружения `VIDEO_URL`).
- **Очистка завершённых контейнеров**: отслеживает состояние контейнеров и останавливает/удаляет завершённые.
- **Логирование**: пишет события работы в файл `container_manager.log`.

### Структура проекта

- `container_manager.js` — основной скрипт менеджера контейнеров.
- `availability_detect.sh` — скрипт для вычисления максимально допустимого числа контейнеров.
- `cleanup_containers.sh` — вспомогательный скрипт для очистки контейнеров (если используется).
- `dummy_script.sh` — примерный/тестовый скрипт.
- `DummyDockerfile` — пример Dockerfile для тестового контейнера.
- `container_manager.log` — файл логов (создаётся при запуске).

### Требования

- Node.js (для запуска `container_manager.js`).
- Docker (для управления контейнерами).
- Утилиты Linux:
  - `mpstat` (обычно пакет `sysstat`) — для измерения загрузки CPU.
  - `free`, `awk`, `nproc` — стандартные утилиты GNU/Linux.
- Среда выполнения — Linux (скрипт использует `/proc/loadavg`, `free`, `nproc` и др.).

### Установка и запуск

1. **Склонируйте репозиторий** (или скопируйте файлы проекта) на Linux‑сервер.
2. **Убедитесь, что Docker установлен и запущен.**
3. **Настройте Docker-образ**, который будет использоваться:
   - используйте `DummyDockerfile` как пример, либо замените его на свой образ;
   - контейнер по умолчанию ожидается под именем `dummy-container` (можно переопределить).
4. **Сделайте вспомогательные скрипты исполняемыми**:

   ```bash
   chmod +x availability_detect.sh cleanup_containers.sh dummy_script.sh
   ```

5. **Запустите менеджер контейнеров**:

   ```bash
   node container_manager.js <имя_контейнера>
   ```

   Если `<имя_контейнера>` не указано, будет использовано значение по умолчанию `dummy-container`.

Логи работы будут записываться в файл `container_manager.log` в корне проекта.

### Переменные и параметры

- **`MAX_LOAD_PERCENT`** — максимальная допустимая нагрузка CPU/памяти для запуска новых контейнеров (по умолчанию 80%).
- **`CHECK_INTERVAL`** — интервал проверки в миллисекундах (по умолчанию 1000 мс).
- **`CONTAINER_NAME`** — имя Docker-образа/контейнера, передаётся первым аргументом в командной строке.
- **`VIDEO_URL`** — переменная окружения, передаётся в контейнер при запуске (в текущем примере содержит ссылку на видео YouTube, можно заменить).

### Примечания

- Скрипт ориентирован на работу в Linux‑среде. На Windows его корректный запуск возможен только в окружении, предоставляющем необходимые утилиты и файловую систему `/proc` (например, WSL2).
- Перед использованием в продакшене рекомендуется адаптировать `availability_detect.sh` под вашу инфраструктуру и параметры ресурсов.
