## Bali Scope

Небольшой Node.js‑скрипт для отслеживания сообщений в Telegram‑группе и сохранения их в JSON‑файлы для дальнейшего анализа (датасеты, логирование, обучение моделей и т.п.).

### Возможности

- **Подключение к Telegram через `TelegramClient`**: использует Telegram API (MTProto) и сохранение сессии, чтобы не проходить авторизацию при каждом запуске.
- **Отслеживание сообщений в заданной группе/канале**: слушает события в группе по `GROUP_ID`.
- **Фильтрация пустых сообщений и дублей**: в JSON попадают только новые непустые сообщения.
- **Сохранение сообщений по дням**: каждый день создаётся отдельный файл вида `YYYY-MM-DD.json` в папке `messages`.

### Стек и зависимости

- **Node.js** (рекомендуется LTS)
- **Библиотеки**:
  - `telegram` — Telegram MTProto‑клиент
  - `input` — удобный ввод кода/пароля в консоли
  - `axios`, `form-data` — для возможной дальнейшей интеграции с внешними API
  - `node-telegram-bot-api`, `openai` — задел для последующей обработки/отправки сообщений

Список зависимостей см. в `package.json`.

### Установка

1. **Склонировать репозиторий или скопировать проект** в любую директорию.
2. Установить зависимости:

```bash
npm install
```

### Настройка

Основные настройки находятся в `index.js`:

- `API_ID` и `API_HASH` — данные Telegram‑приложения, создаются в [my.telegram.org](https://my.telegram.org).
- `PHONE_NUMBER` — номер телефона Telegram‑аккаунта, который будет использоваться для подключения.
- `GROUP_ID` — идентификатор группы/канала, из которой нужно собирать сообщения.

> **Важно:** текущие значения в репозитории заданы напрямую в коде. Для продакшен‑использования рекомендуется вынести их в переменные окружения или отдельный конфигурационный файл, чтобы не хранить чувствительные данные в репозитории.

### Как это работает

1. При первом запуске клиент пытается авторизоваться:
   - запрашивает номер телефона (из кода),
   - код подтверждения,
   - пароль (если включена двухфакторная аутентификация).
2. После успешной авторизации в консоль выводится строка сессии — она сохраняется в `StringSession`, чтобы повторно не проходить логин.
3. Клиент подключается к Telegram и начинает слушать новые сообщения в указанной группе/канале.
4. Каждое новое сообщение:
   - игнорируется, если пустое,
   - проверяется на дубликат в файле за текущий день,
   - при отсутствии дубля добавляется в массив и сохраняется в файл `./messages/YYYY-MM-DD.json` в формате:

```json
{
  "sender": "ID пользователя",
  "content": "Текст сообщения",
  "date": "2026-04-03T12:00:00.000Z",
  "role": "user"
}
```

### Запуск

```bash
node index.js
```

При запуске в консоли появятся сообщения об авторизации и информация об отслеживаемой группе. Новые сообщения будут выводиться в лог и параллельно сохраняться в JSON‑файлы.

### Возможные направления развития

- **Интеграция с LLM/`openai`**: автоматический анализ, классификация и сведение сообщений.
- **Телеграм‑бот на базе `node-telegram-bot-api`**: ответы пользователям, реакция на триггеры в собранных сообщениях.
- **UI‑панель** для просмотра и фильтрации сохранённых сообщений.
- **Гибкая конфигурация** (env‑переменные, `.env` файл, конфиг‑файл).
